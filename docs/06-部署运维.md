# 06 · 部署运维

## 1. 目标机

- Ubuntu 24.04.4
- Python 3.12
- 4 核 / 11G（最低 2 核 / 4G）
- sudo 可用
- 网络：演示时 10.2.102.143；换网络后需同步白名单

## 4. Suricata

```bash
sudo python3 scripts/patch_suricata.py
sudo install -m 644 deploy/suricata/local.rules /var/lib/suricata/rules/local.rules
sudo nginx -t   # 如同时改 nginx
sudo suricata -T -c /etc/suricata/suricata.yaml
sudo systemctl restart suricata
```

- 无线网卡 AF_PACKET ring 不可用，因此使用 `--pcap`，同时抓 `wlp1s0` 和 `nw-kali0`。
- `deploy/suricata-override.conf` 会被 `deploy.sh` 安装到 systemd drop-in。
- 规则子集：`emerging-scan.rules` + `emerging-dos.rules` + local。
  不加载 decoder-events（实验网 veth checksum 噪声）；完整 ET Open 可在网络稳定时补齐
  exploit/malware。

## 5. nginx + ModSecurity

```bash
sudo install -m 644 deploy/nginx/nightwatch.conf /etc/nginx/sites-available/nightwatch
sudo ln -sf /etc/nginx/sites-available/nightwatch /etc/nginx/sites-enabled/nightwatch
sudo install -m 644 deploy/nginx/modsec/main.conf /etc/nginx/modsec/main.conf
sudo install -m 644 deploy/nginx/modsec/crs-overrides.conf /etc/nginx/modsec/crs-overrides.conf
[ -f /etc/nginx/modsec/ai-rules.conf ] || \
  sudo install -m 644 deploy/nginx/modsec/ai-rules.conf /etc/nginx/modsec/ai-rules.conf
sudo touch /var/log/nginx/modsec_audit.json /var/log/nginx/nw_access.log
sudo chown www-data:adm /var/log/nginx/modsec_audit.json /var/log/nginx/nw_access.log
sudo chmod 640 /var/log/nginx/modsec_audit.json /var/log/nginx/nw_access.log
sudo nginx -t && sudo systemctl restart nginx
```

关键点：

- 审计日志用 `modsec_audit.json`，避开 nginx 包 `/var/log/nginx/*.log` 的 rename 轮转；
- 轮转用 copytruncate；
- 动态 WAF 规则用 `nw-waf`，内部 `restart nginx`（reload 不重载 ModSecurity 规则）。

## 6. nftables

```bash
sudo install -d -m 755 /etc/nftables.d /etc/nightwatch
sudo install -m 644 deploy/nftables-nightwatch.nft /etc/nftables.d/nightwatch.nft
sudo install -m 755 deploy/nw-fw /usr/local/sbin/nw-fw
sudo install -m 644 deploy/fw-allow /etc/nightwatch/fw-allow
sudo install -m 440 deploy/sudoers.d/nightwatch /etc/sudoers.d/nightwatch
sudo visudo -c
sudo nft -c -f /etc/nftables.d/nightwatch.nft
sudo /usr/local/sbin/nw-fw init
```

验证：

```bash
sudo /usr/local/sbin/nw-fw status
sudo /usr/local/sbin/nw-fw ban 10.255.255.1 120
sudo /usr/local/sbin/nw-fw unban 10.255.255.1
```

**新开一个 SSH 会话**确认 22 仍通，再继续。

## 7. systemd

三个 unit：

```ini
nightwatch.service         -> python -m app.cli daemon
nightwatch-demo.service    -> python -m app.cli demo site --host 127.0.0.1 --port 8082
nightwatch-fakessh.service -> python -m app.cli demo fake-ssh --port 2222
```

安装：

```bash
sudo install -m 644 deploy/nightwatch.service deploy/nightwatch-demo.service \
  deploy/nightwatch-fakessh.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now nightwatch nightwatch-demo nightwatch-fakessh
```

`nightwatch.service` 需要 `NoNewPrivileges=false`（sudo 调 nw-fw/nw-waf）、
`SupplementaryGroups=adm`（读 suricata/WAF 日志）、`EnvironmentFile=-data/agent.env`。

## 8. 模型密钥


## 9. 换网络/IP

需要同步四处：

1. `config.toml` → `enforce.whitelist_ips`
2. `/etc/nightwatch/fw-allow`
3. nft `nw_allow`（`nft add element inet nightwatch nw_allow { ... }`）
4. `scripts/patch_suricata.py` 的 `HOME_NET`，重跑并重启 Suricata

## 10. 日志轮转

`deploy/logrotate.d/nightwatch`：

- `eve.json`：copytruncate

- `nw_access.log`：create + nginx USR1

## 12. 排障

| 现象 | 处理 |
|---|---|
| 8080 不通 | 正常：CLI 版没有 Web；用 `./nightwatch status` |
| 8081 不通 | `systemctl status nginx`；`nginx -t` |
| WAF 不拦 SQLi | `grep SecRuleEngine /etc/nginx/modsec/main.conf`；`nginx -t`；`restart` |
| WAF 403 但无 waf_alert | 检查审计路径 `.json` 与 `logs` 权限；`ls -l /var/log/nginx/modsec_audit.json` |
| 外部扫描没告警 | `systemctl status suricata`；确认 override 用 `--pcap`；`grep wlp1s0 /var/log/suricata/suricata.log` |
| nft 封禁没落地 | `./nightwatch fw-status`；`sudo -n nw-fw status`；检查 sudoers |
| AI 不可用 | `./nightwatch info` 看 key_present；`data/agent.env`；重启 |
| 值守不跑 | `./nightwatch autopilot on`；等 30s；看 `status` |
| SSH 被锁 | 不会：nft 22 在 drop 前 accept；检查 `nft list table inet nightwatch` |
| 换 IP 后管理机被误封 | 同步四处白名单；用 22 端口 SSH 解封 |

# 07 · 演示脚本（3 分钟）

## 1. 场景

- 服务器：`10.2.102.143`，CLI daemon + TUI
- 攻击机：Kali VM，NAT 模式（`10.0.2.15`），服务器看到出口 `10.2.31.236`
- 目标：`http://10.2.102.143:8081`（WAF → 演示站 8082）

> 校园网可能对 VM MAC 做准入，桥接会“能上网但到 10.2.102.x 不通”；
> 此时用 NAT。22 端口在 nft drop 之前放行，管理 SSH 不受封禁影响。

## 2. 演示前

```bash
cd ~/nightwatch
bash scripts/demo_reset.sh     # 解封全部、清 nft、清 WAF 规则、暂停 daemon autopilot
./nightwatch battle --tui
```

Kali：

```bash
ping -c 2 10.2.102.143
curl -s -o /dev/null -w "%{http_code}\n" http://10.2.102.143:8081/
```

期望 200，TUI 顶部 `DEFCON 3`、`active bans 0`。

## 3. 逐秒脚本

| 时间 | 你（Kali） | 屏幕（TUI） |

| 0:00 | — | 双栏作战室，DEFCON 3，记分牌 0/0 |

| 0:45 | TUI 按 `u` 解封 | 封禁清空 |
| 0:50 | `sudo hping3 -S -c 2000 -i u2000 -p 8081 10.2.102.143` | 左：`NET_ALERT NW SYN FLOOD` → `BAN NET_DOS`；右：AI 确认 |
| 1:20 | 按 `u` | 清空 |

## 4. 画面要点

WAF SQLi：

```text
13:09:22  WAF_ALERT  #...  10.2.31.236  SQL Injection Attack Detected via libinjection
13:09:22  BAN        #...  10.2.31.236  WAF_SQLI.v1  WAF_SQLI
  [TOOL] attack_chain(...)
  [OK] 8ms
  [TOOL] firewall_status({})
  [OK] count=1 timeout=3600
  [AGENT] 10.2.31.236 已被 WAF_SQLI 封禁，证据 #...
```

SYN Flood：

```text
NET_ALERT  NW SYN FLOOD 8081 >=200/10s
BAN        NET_DOS.v1  NET_DOS
```

蜜罐：

```text
HONEYPOT  /admin
BAN       HONEYPOT.v1  HONEYPOT
```

## 5. 降级

1. TUI 异常：`./nightwatch battle --plain`
2. 模型不可用：`./nightwatch battle --tui --no-model`
3. Kali 不通：服务器 netns：
   ```bash
   sudo ip netns exec nw-attacker nmap -sS -Pn -p 1-1024 10.200.0.1
   sudo ip netns exec nw-attacker curl http://10.200.0.1:8081/admin
   ```
4. 校园网过滤 nmap：网络层用 `hping3`；扫描用 `sqlmap`/`nikto`/蜜罐
5. 时间不够：砍掉 2:05 的 AI 写规则，保 SQLi / SYN Flood / 蜜罐

## 6. 收尾

```bash
bash scripts/demo_reset.sh
./nightwatch autopilot on
```

## 7. 答辩三句话

1. AI 不在裁决链路上：确定性规则负责封禁，AI 负责调查、解释、补处置。
2. 每次处置都有证据：事件号、原始日志、CRS/Suricata 签名、哈希链，可回滚。
3. Kali 是红队：只在授权实验网/授权服务器上验证防线。
